# МикРоББокс 0.1

**Миниатюрный робот на базе ESP32CAM с модульной архитектурой**

## 🎯 Типы роботов

МикРоББокс 0.1 поддерживает три типа роботов из единой кодовой базы:

### 🚗 МикроБокс Классик
**Полнофункциональный управляемый робот**
- Управление через веб-интерфейс, клавиатуру, геймпад, VR
- Видеострим с камеры в реальном времени
- Светодиодные и звуковые эффекты
- Идеален для телеуправления и экспериментов

### 🛤️ МикроБокс Лайнер
**Автономный робот следующий по линии**
- PID-контроллер для следования по линии
- Камера 96x96 ЧБ для анализа линии
- Кнопка для запуска автономного режима
- Опциональное ручное управление для позиционирования
- Индикация режима работы светодиодами

### 🎮 МикроБокс Брейн
**Модуль управления для других роботов**
- Камера и WiFi управление для любого робота
- Трансляция команд в различные протоколы:
  - PWM (1000-2000 мкс, 4 канала)
  - PPM (8 каналов)
  - SBUS (16 каналов)
  - TBS Crossfire (8 каналов)
- Подключается к существующим роботам (StackForce, дроны и т.д.)

- **WiFi**: Поддержка AP и Client режимов с автоматическим переключением
- **mDNS**: Доступ по имени {6mac}.microbbox.local

- **Моторы**: MX1508 драйвер моторов (пины 12,13,14,15)

- **Бузер**: Активный бузер на пине 16

## ⚙️ Конфигурация через platformio.ini

МикРоББокс 0.1 использует современную систему конфигурации в стиле **ExpressLRS**:

- ✅ **Нет препроцессорных директив** в коде
- ✅ **Автоматическая конфигурация** компонентов для каждого типа

- ✅ **Чистая архитектура** - тип робота определяется при сборке

### Как это работает

Каждый тип робота автоматически получает нужные компоненты:

**Classic:** Моторы + Камера + WiFi + LED + Бузер + Управление  
**Liner:** Моторы + Камера (96x96 ЧБ) + WiFi + LED + Кнопка + Следование по линии  
**Brain:** Камера + WiFi + Трансляция протоколов (PWM/PPM/SBUS/TBS)

Настройка происходит через `target_config.h` и `hardware_config.h` - вручную ничего менять не нужно!

## Подключение

### Автоматическое подключение (рекомендуется)
При первом запуске робот создаст точку доступа с именем `MICROBBOX-XXXXXX` (где XXXXXX - последние 6 символов MAC адреса):
1. Подключитесь к WiFi сети `MICROBBOX-XXXXXX` (пароль: `12345678`)
2. Откройте браузер и перейдите на `192.168.4.1`
3. Нажмите кнопку ⚙️ (Настройки) в интерфейсе
4. В разделе "WiFi настройки" выберите режим "Подключение к сети (Client)"
5. Введите SSID и пароль вашей WiFi сети
6. Нажмите "Сохранить WiFi" и затем "Перезагрузить устройство"

После перезагрузки робот автоматически подключится к вашей сети. Если подключение не удастся, робот вернется в режим точки доступа.

### Доступ к устройству

**По IP адресу:**
- В режиме AP: `192.168.4.1`
- В режиме Client: смотрите IP в Serial Monitor (115200 baud) или в настройках роутера

**По mDNS имени:**
- `http://{6mac}.microbbox.local` (где {6mac} - последние 6 символов MAC)
- Например: `http://a1b2c3.microbbox.local`

### Ручная настройка сети (устаревший метод)
Вы также можете настроить сеть до прошивки, изменив в `include/hardware_config.h`:
```cpp
#define WIFI_MODE_CLIENT true  // false для режима точки доступа
#define WIFI_SSID_CLIENT "ROS2"
#define WIFI_PASSWORD_CLIENT "1234567890"
```
**Примечание:** Настройки из веб-интерфейса имеют приоритет над настройками в config.h

### Режим Access Point (если WiFi недоступен)
Если подключение не удалось, робот автоматически создаст точку доступа:
1. Подключитесь к WiFi сети `MICROBBOX-XXXXXX` (пароль: `12345678`)
2. Откройте браузер и перейдите на `192.168.4.1`

## Обновление прошивки

### Автоматическая проверка обновлений

При запуске робот может автоматически проверять наличие новых версий на GitHub (если включена опция в настройках).

### Обновление через веб-интерфейс

1. В веб-интерфейсе нажмите кнопку **⚙️ Настройки**
2. Прокрутите до раздела **🔄 Обновление прошивки**
3. Нажмите **"Проверить обновления"** чтобы найти новую версию на GitHub
4. Или загрузите файл прошивки вручную:
   - Нажмите **"Выбрать файл .bin"**
   - Выберите файл прошивки (например, `microbox-v1.0.0-release.bin`)
   - Нажмите **"Загрузить прошивку"**
5. Дождитесь завершения обновления и перезагрузки устройства

### Настройки обновлений

- **Автоматически проверять обновления при запуске** - при каждом запуске робот будет проверять GitHub на наличие новых версий
- **Не предлагать обновления** - отключает автоматические уведомления об обновлениях
- **Канал обновлений** - выбор между стабильными (stable) и dev (разработческими) версиями

### Каналы обновлений

#### Stable (По умолчанию)
Стабильные релизы из ветки `main` для production использования.

#### Dev (Для разработчиков)
⚠️ **Development сборки** из веток `develop` и `feature/*` для тестирования новых функций.

**Когда использовать dev канал:**
- Вы хотите протестировать новые функции до релиза
- Вы разработчик и нужно проверить изменения
- Вы понимаете риски использования нестабильных версий

**Как переключиться на dev канал:**
1. Откройте **⚙️ Настройки** → **🔄 Обновление прошивки**
2. В разделе "Канал обновлений" выберите **Dev (Разработческий) ⚠️**
3. Нажмите **"Проверить обновления"**
4. Доступные dev сборки будут показаны для установки

## Архитектура кода 2.0

### Принципы SOLID, DRY, KISS

Проект полностью переработан с учетом лучших практик:

- **S**ingle Responsibility: Каждый класс имеет одну ответственность
- **O**pen/Closed: Легко расширяется без изменения существующего кода
- **L**iskov Substitution: Любой тип робота заменяет базовый класс
- **I**nterface Segregation: Маленькие, сфокусированные интерфейсы
- **D**ependency Inversion: Зависимость от абстракций, а не реализаций

### Основные классы

**Интерфейсы:**
- `IComponent`: Базовый интерфейс всех компонентов
- `IRobot`: Интерфейс робота
- `IMotorController`: Интерфейс контроллера моторов

**Базовые классы:**
- `BaseRobot`: Общая функциональность всех роботов (WiFi, Camera, WebServer)
- `MX1508MotorController`: Контроллер моторов MX1508

**Реализации роботов:**
- `ClassicRobot`: Управляемый робот (наследует BaseRobot)
- `LinerRobot`: Робот следующий по линии (наследует BaseRobot)
- `BrainRobot`: Модуль управления (наследует BaseRobot)

**Вспомогательные:**
- `WiFiSettings`: Управление настройками WiFi
- `FirmwareUpdate`: Система OTA обновлений
- `FirmwareUpdate`: Система обновления прошивки

### HTTPS поддержка

#### Вариант 1: Docker Proxy (Рекомендуется - Простая настройка)

**Новое!** Простая Docker композиция для проксирования ESP32 на HTTPS с валидными SSL сертификатами.

**Преимущества:**
- ✅ Автоматическая настройка одним скриптом
- ✅ Let's Encrypt сертификаты с автообновлением
- ✅ Работает на любой системе (ноутбук, Raspberry Pi, сервер)
- ✅ Проксирование двух портов ESP32 (80 и 81) на один HTTPS (443)
- ✅ Полная совместимость с WebXR
- ✅ Самоподписанные сертификаты для локальной сети

**Быстрый старт (5 минут):**
```bash
cd docker/
./scripts/setup.sh
# Отредактировать .env (ESP32_IP, DOMAIN_NAME)
./scripts/generate-selfsigned-cert.sh  # или obtain-certificate.sh для Let's Encrypt
```

#### Вариант 3: HTTPS на ESP32 (Не рекомендуется)

Встраивание SSL в ESP32 возможно, но имеет существенные недостатки:

1. **Генерация самоподписанного сертификата**
   - Использовать OpenSSL для создания сертификата и ключа
   - Встроить сертификат в прошивку

2. **Изменения в коде**
   - Заменить `AsyncWebServer` на защищенную версию
   - Добавить обработку SSL/TLS сертификатов
   - Учесть увеличение использования памяти (~40-50KB)

3. **Ограничения**
   - ❌ Браузеры будут показывать предупреждение о самоподписанном сертификате
   - ❌ WebXR не будет работать (требует валидный сертификат)
   - ❌ Требуется больше вычислительных ресурсов ESP32
   - ❌ Может снизить производительность видеостриминга

**Вывод:** Для локальной сети без WebXR HTTP достаточно безопасен. Для WebXR используйте nginx reverse proxy.

## WiFi Настройки

### Хранение настроек
Настройки WiFi хранятся в энергонезависимой памяти (Preferences) и сохраняются между перезагрузками:
- SSID сети
- Пароль сети
- Режим работы (Client/AP)
- Имя устройства

### Имя устройства
Каждое устройство имеет уникальное имя формата `MICROBBOX-XXXXXX`, где XXXXXX - последние 6 символов MAC адреса.
Это имя используется для:
- SSID точки доступа
- Hostname в сети
- mDNS имя (например, `a1b2c3.microbbox.local`)

### Сброс настроек
Для сброса настроек WiFi к значениям по умолчанию можно:
1. Через веб-интерфейс: изменить настройки и сохранить новые
2. Программно: вызвать `wifiSettings->reset()` в коде
